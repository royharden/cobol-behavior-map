`cobolmap.oracle.requests.prepare_request(OracleRequest | CandidateRequest) -> ExecutionPlan` validates exact closed models and canonical nested contracts, then constructs pure staging bytes, argv, cleared environment and input stream data. No function opens files or invokes shell/subprocess/exec/eval. TaskBinding retains original versus changed oracle-source and raw edit identity. Observation source_sha256 binds task.original; the actual compiled task.oracle_source remains separately pinned in every retained request/plan. Original and changed task groups must never be conflated.

OracleRequest carries task/source Blob/case/OracleToolchain/purpose/authorization/allowed_return_codes/trace. Source Blob must equal the task's exact oracle_source ArtifactRef, bind actual bytes, be nonempty bounded ASCII <=65536 bytes. The plan stages unchanged bytes at /stage/program.cbl and present input (including present-empty) at /work/input.dat; absent input has no staged file. Explicit compiler argv is /opt/gnucobol/bin/cobc -x -free -std=default -O0 [-ftraceall] -o /work/oracle /stage/program.cbl, then /work/oracle. Trace is restricted to unchanged original source with a supplied approved framing reference. Paths and options are fixed; source/artifact names cannot interpolate argv. The backend must execute run only after successful actual compilation in the same isolated request and retain both phase results. No compiler fallback, parser/model output or hand-authored expected observations exists.

Matching compiler/config/runtime/libcob/default.conf hashes are checked structurally. CandidateToolchain retains separate shared ExecutionPins and actual runtime version/package/runtime/info references, approved entry launcher reference and SDK manifest digest. No installed measurements are supplied here.

CandidateRequest carries task/candidate Blob/helpers/case/CandidateToolchain/purpose/authorization/allowed codes. Exactly eight SDK-relative helpers are accepted: entry.py, cobolmap/__init__.py, cobolmap/shared/__init__.py, cobolmap/shared/decimal_shim.py, cobolmap/shared/codec.py, cobolmap/translate/__init__.py, cobolmap/translate/runtime.py, cobolmap/translate/errors.py. These are supplied artifacts, not copied or authored by this package. Candidate stages only candidate.py plus that closure under /stage and receives canonical native CaseBundle JSON through stdin. No oracle input file is mounted for candidate execution. Fixed argv is /opt/python/bin/python3 -I -B /stage/sdk/entry.py. The future externally approved m10-run-case-v1 adapter must load only that staged candidate/SDK, decode the exact presence/ordered-record case framing and invoke its run_case ABI inside containment, returning bounded actual ordinary channels and faults. No launcher/decoder/import screener is shipped; no adapter correctness or hostile-code safety is established. Candidate modeled values never become oracle expected values.

`run_request(request, *, backend=None, conformance=None, preparation_authority=None, study_authority=None) -> RunnerResult` is the only future orchestration entry. It re-plans exact canonical requests itself; callers cannot inject custom ExecutionPlan argv or mounts. Defaults return pending with no backend call. BackendConformance supplies backend ID, exact profile/role/image/policy digest and actual measurement receipt; study candidates also require a hostile-fixture receipt. Preparation allows dev/probe tasks only and uses a distinct PreparationAuthority.verify_preparation(plan,conformance); study uses StudyAuthority.verify_study(plan,conformance). The authority authenticates exact authorization/scope and actual isolation/conformance. Limited preparation may need to run the containment fixtures themselves under separately authorized controls, so prior P2/complete fixture receipts are not a circular prerequisite. No such permission exists now. Preparation observations have admission_authority=None and cannot satisfy shared admitted-study gates.

TrustedBackend.execute(plan)->RawExecution is an injected protocol only. Missing/raising/non-None authority refuses. The trusted control plane must authenticate who supplied those authority/backend objects; a duck-typed object returning None is not proof. No default verifier, approval flag, fixture runner or authority implementation is supplied. RawExecution retains exact plan/backend/execution_id/runtime receipt and one candidate run phase or compiler+run oracle phases (compiler-only on actual compiler failure). Each PhaseResult retains output presence/exact bytes, stdout/stderr, signed raw return, raw outcome, flags and integer CPU/wall microseconds. `check_consistency(records: tuple[RunnerResult,...], *, authority=None) -> ConsistencyReport` retains all supplied closed records, including pending/invalid/quarantined records. Groups bind exact TaskBinding/case/purpose/authorization; candidate results are quarantined, never substituted. Each oracle group needs >=2 distinct untraced actual ordinary executions; duplicate (backend_id,execution_id) or per-execution runtime receipt SHA256 is quarantined while retaining every entry. The external authority must authenticate those IDs and each distinct receipt against actual execution, rather than caller-created labels; one shared batch receipt cannot substitute for distinct per-execution receipts. trace records compare all ordinary presence/bytes/stdout/stderr/return and execution pins against the same group. Different original/changed tasks remain separate groups. Any invalid, missing, faulted or differing record blocks consistency; it is not dropped from the returned record tuple. A separate ConsistencyAuthority.verify_records must authenticate all exact runtime and trace records/receipts; no authority defaults to pending. Structural models/evidence_mode/receipt hashes alone cannot authenticate results or establish scheduled-scope completeness. Caller must separately bind this explicit tuple to the required schedule; this helper does not certify a complete study.
