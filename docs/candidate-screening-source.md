# Candidate source screening

Private original r6 P4 supplement, static construction/runtime-unverified. No candidate/fixture was imported, compiled, screened, executed or used to create a request/result/receipt during construction. No existing consumer, oracle, backend or authority path changed. The APIs below describe future calls only.

`from cobolmap.sandbox import screen_candidate, ScreenContext, ScreenResult, ScreenReason`. `screen_candidate(candidate:bytes|str, *, context:ScreenContext|None=None) -> ScreenResult` screens only the closed `translator-plan-v1` wrapper emitted by the current translator. Supported module: optional inert docstring; exactly `from cobolmap.translate.runtime import run_plan`; a single literal `PLAN = {...}`; exactly `def run_case(input_present, records): return run_plan(PLAN, input_present, records)`. Import aliasing, other imports/bindings, decorators/defaults/annotations/variadics, async/classes, comprehensions, assignments/side effects outside the one literal, attribute/subscript/method calls, arbitrary operators, dynamic code/import/eval/exec/open/network/process/reflection and all other executable shapes refuse. No candidate expression is evaluated; no compile, eval, literal_eval, import hook or runtime function is called. An ast.parse operation creates syntax data only.

This deliberately supports the generated translator form. Arbitrary Python/model candidates outside it refuse, even if a human considers them harmless. PLAN data is inert bounded literal data, with a closed version/source/filename/container root and source-pointer binding checks. This screen does not duplicate translator/parser DSL semantic validation, re-prove loop bounds or certify PLAN effects/parity. A malformed literal PLAN can still fail in the runtime. Candidate-caused runtime failures stay failures; the screen does not convert them to successful observations. Supporting broader Python requires a new explicit profile/grant and review.

ScreenContext requires task_id, program_id, original_source:oracle.pins.Blob, source_filename (the parser's logical relative filename), candidate_sha256, toolchain:oracle.pins.CandidateToolchain, helpers:tuple[Blob,...], entry_approval:ArtifactRef|None. Source artifact path and logical pointer filename are distinct commitments; both are retained, neither guessed from the other. Exact context models are revalidated from detached dumps, closing constructed-model bypasses. Raw original/candidate/helper bytes must match references; no CRLF/whitespace/sign normalization. Missing context returns pending. Missing/invalid helper or source commitments refuse. Missing external entry approval returns pending. Entry bytes must actually be supplied and equal the r5 launcher reference; no invented adapter source or approval receipt exists here.

Helper paths and manifest hashing reuse the integrated oracle.pins SDK_PATHS/helper_digest, preserving the exact r5 eight-file closure: entry.py; cobolmap/__init__.py; cobolmap/shared/{__init__,decimal_shim,codec}.py; cobolmap/translate/{__init__,runtime,errors}.py. The sorted canonical ArtifactRef manifest, raw byte hashes, shim pin and launcher reference must agree. Helpers are each bounded by existing Blob1MiB validation; exactly8 are allowed. Only the candidate's single fixed import is screened. Helper/entry source correctness, dependency transport/closure, installed library behavior, content provenance and approval authenticity remain external obligations. A matching hash or present entry_approval ref is not authority. No ambient SDK fallback is added.

Limits precede downstream parsing/expansion where possible: candidate <=65536 raw bytes and4096 lines; original source <=65536 ASCII bytes/200lines;32768 lexical tokens;64 bracket nesting;32768 AST nodes and128 AST depth, checked before scheduling child nodes; literal depth64, string length8192, integer magnitude <10^12, sequence/mapping size4096. Only ordinary unprefixed string tokens and <=12 digit decimal integer tokens are admitted; one unary minus may precede an integer. File encoding cookies are rejected because ast.parse(str) and Python file loading could otherwise decode the same raw bytes differently. Literal values are decoded manually through whitelisted AST nodes with no expression evaluation; duplicate mapping keys/unpacking refuse. Source span checks use one precomputed newline index rather than repeatedly hashing/scanning the full source. All traversal sizes derive from the bounded parsed tree. Source/AST ceilings can refuse valid generated code; false-positive/negative behavior is untested.

These limits bound screen input/work domains but do not establish a precise wall/memory guarantee for Python's tokenizer/parser. Future hostile-input invocation still requires an actual approved bounded process/environment; no current invocation is authorized. Syntax/tokenizer/encoding/recursion/memory refusals return a structured reason. Every result retains exact candidate ArtifactRef where a bounded raw hash was computable, canonical context/source/tool/helper/entry commitments when valid, computed helper digest and available token/node/depth counts. Oversize/type-invalid inputs refuse before hashing/parsing and have no invented digest. Reason codes and optional AST line/zero-based byte-column identify the stage; raw exception text is not forwarded. Pending/refused results confer no partial pass.

ScreenResult status is pending|refused|screened, profile translator-plan-v1, with structured ScreenReason records. execution_authorized, containment_verified and study_admitted are hard False. A screened result certifies only that the bounded source matched this syntax/pin screen. It never authenticates helpers/approval, establishes hostile-code safety, proves compiler/model behavior, authorizes backend/provider dispatch, grants P2 admission or replaces sandbox/OS controls and externally designated authority. The integrated r5 default missing-backend/authority refusal remains unchanged; no consumer uses screen status as authorization.

Deferred: actual source/profile/refusal cases, translator-output joins, exact byte/filename/pointer/hash vectors, malformed context/SDK/entry cases, source/token/depth/node/literal limits, encoding/parser mismatch cases and false positives/negatives; approved entry and installed runtime dependency/transport validation; adversarial arbitrary Python and helper behavior; all OS containment/authority/authenticity/R07/P2 checks. Verification here is source AST/diff/manual review only, never execution or independent evidence.
