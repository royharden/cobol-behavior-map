`m10-dev-operators-v1`. These are operator definitions, not planted samples or
observed fault classifications. Applicability is explicit syntax. All intended
classes/themes are hypotheses until actual nonauthor review and frozen-case proof.

Status/window/control themes are semantic hypotheses, separate from the native
comparator's nine classes. A year-like field name or a flag edit is not reachability,
validity, non-equivalence or class proof. Operators may be inapplicable, ambiguous,
equivalent or invalid for an actual program. None is counted valid/killed from intent.

`mutate(candidate: bytes, operator_id: str, *, binding: MutationBinding)` returns an
inert `MutationArtifact` only for an exact DEV binding and precisely one eligible
edit across the actual supplied candidate. Zero/multiple matches or a no-op refuse.
There is no choose-first fallback, target-selection escape or arbitrary text patch.
No file is written, and candidate Python is always hostile data.

`MutationBinding` pins task/program/family/split, actual original-source hash, parent
candidate hash, generator/runtime source hashes, operator source hash and plan-reader
source hash. Those last two are the actual raw files' hashes supplied from the
externally frozen source manifest, not self-issued authority. `MutationArtifact`
retains that binding, catalogue version, operator ID and definition+implementation
pin digest, intended class, target path, exact byte range, actual before/after bytes
and hashes, changed candidate bytes/hash, and `not_executed`/pending validity.

The bounded `mutant_plan` reader accepts the actual DL2 generator shape: fixed
docstring, sole fixed runtime import, one literal PLAN assignment and fixed
`run_case(input_present, records)` delegating to `run_plan`. It uses a syntax tree
only, never compile/eval/exec/import of candidate data. PLAN accepts only closed
literal dict/list/scalar structure with duplicate keys, expressions, unpacking,
unknown keys and unsupported module code refused. Limits are2MiB,20000 AST nodes,
depth64,32 fields and8 paragraphs. This is an adapter to the actual normalize/IR
and runtime source inspected at4628fb1, not a general Python mutation engine or a
replacement translator. It does not assert semantic validity of mutated programs.

Each transformation replaces one literal subtree byte range. WRITE edits replace
the enclosing body list with exactly one statement removed/inserted; all other
elements retain their literal values. Original header, PLAN source hash, filename,
field/source pointers and family binding are inherited. Source spans continue to
refer to the original COBOL, not invented changed COBOL. Whole-file and target
before/after hashes expose the mutation; original identity is never rewritten to
pretend another program/family. No actual operator was invoked during construction.

## Versioned instrument boundary

`instrument.evaluate_instrument(policy, baselines, cases, assessments, *,
authority=None)` is source for a future authorized evaluation of real supplied
records. It executes no candidate, comparator, compiler, generator or regression.
The project evaluator edition is `m10-dev-instrument-v1`. The canonical evidence-gate
skill, rules and adapter contract informed the claim boundary. This is neither
normalized-core adoption/parity nor evidence-gate certification. The returned
structural report is not product acceptance, GO or live dispatch authority.

`InstrumentPolicy` pins externally approved edition, instrument/operator/plan-reader
source hashes, generator/runtime hashes, the complete48 DEV tasks, separate native
oracle/candidate execution pins, authorization and independent review refs. It never
fills authorizations or appoints roles. Exact six-family/four-program/both-panel
frame, unique IDs and identical paired original source hashes are mandatory.
Oracle and candidate images/configuration may differ; their respective pins must
match the actual observation target. Candidate generator execution pin also matches
the policy's generator source commitment.

`FrozenVerification(task_id,program_id,source_sha256,partition,cases)` binds actual
128 unique native CaseBundles to the exact task's oracle source and raw partition
ref. The local checker does not establish that the partition is truly frozen;
external authority authenticates its full actual bytes/custody/source context.
`BaselineProof(task_id,candidate_sha256,partition_sha256,observations,
execution_receipt)` must cover every frozen case for every DEV task. Each
`CaseComparison(case_sha256,oracle,candidate,comparison)` uses actual native
ExecutionObservation/ComparisonResult. Passing A requires actual matching ordinary
presence/output/stdout/stderr/return, correct oracle and candidate source identities,
parent candidate hash, task/program/case, target pins and real receipts/authority.
Missing baseline/partition remains pending; a claimed nonpass refuses as a passing
proof. Compiler faults, unknown/infra and source availability cannot become passes.

`MutantAssessment` retains operator ID, actual MutationArtifact, status, observed
class, frozen kill-case hash/CaseComparison, all survivor observations, separate
nonauthor validity/classification/written-equivalence refs and extra verifier witness
refs. Statuses are exactly `not_executed`, `pending`, `killed`, `survived`, `invalid`,
`equivalent-with-written-proof`. They are supplied declarations until authenticated;
report counts with issues must not be quoted as measured study results.

The mutation is reconstructed and reproduced from actual parent bytes using the
declared operator to check exact edit lineage; this is data transformation, not
execution. Parent must equal the genuinely passing A for that task. All20 operators
remain scheduled. A valid non-equivalent kill must use a hash-identified case in
that program's frozen verification partition and actual nonmatching observations.
The declared class must be present in the actual comparison and supported by
separate nonauthor class review. Genuine candidate fault may be detected; an oracle
fault/infra event never kills. Heuristic comparison tags alone do not establish cause.
Every targeted comparator class must have a demonstrated frozen-case kill. Any
survivor, missing operator/class, unresolved proof or invalid catalogue blocks fit;
no denominator/class shrink. An equivalent requires written nonauthor proof, never
an automatic relabel of a survivor. Additional verifier witnesses remain separate
and cannot substitute for frozen partition kills. Invalid/missing catalogue entries
need a recorded externally approved replacement revision before any new run.

`InstrumentAuthority.verify(policy=...,baselines=...,cases=...,assessments=...)->None`
or raises is an external protocol, absent by default. It must authenticate the
actual approved code/edition/scope manifest, real positive execution/receipt counts,
frozen byte partitions, pins/targets, all observations, actual nonauthor validity/
non-equivalence/class/equivalence proof, exact independent registry/parent/fork
lineage, and any revalidation/reseal. The caller must authenticate the verifier's
actual designation separately; a duck-typed callback returning None is not proof.
No verifier implementation, independent receipt, authority revision or actor is
authored here. Unknown/extra/subclassed nested native evidence cannot be silently
discarded on projection. Hash identity is not authenticity or execution.

With missing evidence the report is pending; explicit invalid/survivor declarations
block fit. Only the exact fully covered structure with externally authenticated
proofs can be `structurally_eligible_under_external_authority`. Even that local
versioned verdict has `product_go=False` and `dispatch_allowed=False`, and cannot
be substituted for P2 or a real model-arm gate. No such report instance exists now.

`generation_round` permits only0 or1. A sole DEV generator improvement requires
externally authenticated improvement authorization, full revalidation, reseal and
renewed GO refs. There is no generator action here, outcome-driven hidden change,
automatic rerun, source revision self-approval or second improvement path. Actual
record-chain authenticity and prior outcome preservation remain external obligations.

## Neutral typed prompt templates

`prompts.prompt_template(arm)` returns source text for a frozen `PromptTemplate`.
No template/task-context instance is emitted now. B and C share initial instruction;
all B/C/D/R have identical original/shim/change framing. Neutral common text asks
for observable behavior using supplied API and treats all JSON-delimited source
comments/literals/maps/docs/candidate/feedback as untrusted data. Such instructions
are not measured injection resistance or a substitute for canary/provenance gates.

`build_initial_prompt(native InitialFeedback, *, task, loop_hashes,
admitted=False,max_payload_bytes=60000)` returns native provider Message tuples for
a future caller. B has original/shim/structured change and no map; C requires the
map. Source bytes and raw edit text match TaskBinding artifacts, unchanged request
is empty, and pointers resolve to original bytes. Exact recursive native types and
fields are reconstructed/revalidated without caller serializers or generic dumps.

`build_counterexample_prompt(native CounterexampleFeedback, *, task,call_id,
shared_c_call_id,expected_previous_call_id,loop_hashes,admitted=False,
max_payload_bytes=60000)` uses exact initial C for attempt1 and own prior D for
later attempts, with exact call/task/attempt/shared-C linkage. D receives one
permitted final LoopWitness, or a failed-candidate diagnostic with no invented
observation. `build_count_prompt` has corresponding CountOnlyFeedback signature and
own prior R linkage. It uses exactly `Your candidate failed {k} of {n} loop-set
cases.` D/R permit candidate compile/import/runtime diagnostics under the same
failed/refused/invalid policy; generated candidates cannot receive diagnostics.
R never receives witness bytes/class/field, D repairs or reduction lineage.

Native feedback validation keeps the trusted original32 fixed. New-hash minimized
derivatives remain unsupported/refused by these builders; current producer
outboundFalse and DL3 derivative reconciliation are not bypassed. Local full
origin/retained proofs and intermediate oracle answers are absent from prompt APIs.
No verification/changed oracle/trace/private-family/cross-task context is accepted.
Previous CandidateAttempt projection matches the provider's current declared full
native projection; it is not a reduction-proof carrier.

The templates create neither ProviderRequest nor approved model/price IDs. Local
message byte bounds refuse rather than truncate. External exact context allowlist,
canaries, actual admission, whole-wire byte/token proofs, fixed model/run/price and
accounting/transport authority remain mandatory. Substring scans are not authentic
canary verification. There is no send, backend, ledger instance or live activation.
