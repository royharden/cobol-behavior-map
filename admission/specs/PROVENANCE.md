# Artifact provenance and custody v1

Original-only preparation. No license is adopted by this document. MIT code/CC0-1.0 data are recommendations awaiting R03, not grants. Original private preparation bytes may be retained under the current assignment; admission/product use/publication stays gated. No held-out author or independent verifier is appointed by this team.

Every program, changed original, probe, candidate, structured request, field/recipe document and generated input artifact needs a provenance sidecar. Sidecar keys: manifest_version=1, artifact_path (relative safe path), artifact_sha256 (actual bytes), artifact_kind, author_callsign, author_harness, author_session_id, created_at (UTC RFC3339), originality_attestation, family_id (nullable for shared instruments), split (`dev|heldout|shared`), brief_sha256, generator_sha256 (null only if not generated), source_sha256 (null for independent shared specifications), parent_artifact_sha256 (null for an original), license_id, license_approval_id, license_status, evidence_paths. Artifact kinds are `source|changed_source|probe|candidate|request|fields|recipe|input|instrument|specification`. Paths must reject absolute/traversal/symlink escapes. Hashes lowercase SHA256; identity strings are labels backed by named sessions, not cryptographic authentication.

Originality attestation states newly authored synthetic content, no prohibited ingestion, and the author's actual contribution/model family. Generated inputs identify deterministic generator/fields/recipe versions and seed/collision counter in a linked manifest. A sidecar never attests human authorship unless true. Unknown authorship/provenance refuses `provenance_missing`; bad hash `provenance_hash`; unsupported ingestion `provenance_excluded`; missing license approval `license_pending`; false/incomplete role separation `independence_pending`. A pending sidecar uses license_status=`pending`, license_id=null, license_approval_id=null, no invented signature. Approved status requires an explicit Roy decision reference; denied remains denied.

Never ingest LegacyCodeBench, NIST CCVS85, DecimalDiff, poc-cobol-java, IBM paper content, opensourcecobol4j source, or client/Gauntlet/partner programs into code/data. Citations and ideas do not authorize copying. Review actual GnuCOBOL notices/compiler/runtime licensing separately; record tool checksums and notices when authorized. No tool image is published. S3 vendor reliance remains separately gated.

## Custody and GO

Builder owns dev/preparation only. Later appointed custodian is a separate session in a different harness, receiving only the frozen specs/briefs and standalone generator, never translator/shim implementation, tuned prompts or dev answers. Nonauthor verifier independently reproduces pins/probes/three deterministically selected dev programs, recipe reachability and custody, without supplying hidden answers. Builders and their review children cannot claim either role. Any hidden exposure retires that set; do not patch a seal silently.

Private heldout-custody/v1 stays OUTER and under appointed control, outside product checkout. Only commitments enter product before burn. Seals bind exact programs/changes/fields/recipes/generated cases/observations/quarantine counts, tool/compiler/config/image hashes, briefs, role/session attestations, family slots/template screens and partition hashes. Exactly32 loop and128 valid verification cases per task; quarantine only candidate-independent oracle faults before seal. Immutable custody event records bind previous commitment, next commitment, actor/session/time/reason/evidence. Integrity hashes cannot prove secrecy or authentic authorship.

Every GO item has checked_by, session_id, harness, timestamp, evidence_paths, result. Builder signs compiler/config/own originality/notices/dev preparation; custodian signs hidden authorship/counts/template checks/independence/seal; verifier signs independent reruns/recipes/reachability/custody; Roy signs staffing/licenses and confirms manifest hash/date. All must pass before P3. Missing or failed items stay PENDING/NO-GO, never downgraded by Dirty Mode or static review. This package supplies no signatures, GO receipt, seal or output observation.
