# Families and change tasks v1

No corpus is authored here. A family is the tuple domain + control-flow template + hazard theme, not an individual program, rename, constant set or variant. Domains are `decimal_fees`, `sequential_status`, `year_window`. Family metadata keys: manifest_version=1, family_id, split, domain, template_id, template_description, hazard_ids, program_ids, author_provenance_sha256. Split is `dev|heldout`; hazards reference H1..H8 in HAZARDS.md. Never make held-out IDs/content available to the builder before authorized burn.

## ProgramManifest

The author-written program manifest has exactly `manifest_version`, `program_id`, `source_sha256`, `family_id`, `split`, `input_fields_sha256`, `output_fields_sha256`, `allowed_return_codes`, `loops`, `hazards`, `provenance_sha256`. Version is integer1; IDs/hashes follow GENERATOR.md; split matches the family. Field documents describe external input/output layouts separately. `allowed_return_codes` is a nonempty sorted unique list of integers0..255, including0; no runtime fault is converted into a declared code. Every RETURN-CODE assignment must resolve to this list by static constant/range reasoning.

`loops` lists every PERFORM UNTIL exactly once in increasing source byte order. Each entry has exactly `target`, `paragraph`, `induction_field`, `initial`, `step`, `relation`, `limit`, `max_iterations`, `proof`. Target is `{file,line,byte_start,byte_end}` resolving to that source statement; paragraph/induction_field are uppercase declared identifiers. Initial/step/limit are signed integer decimal strings; step is nonzero; relation is one SUBSET comparison; max_iterations is integer1..64. Proof is an object with exactly `initialization_span`, `update_spans`, `exit_span`, each span using the same target shape (update_spans is a nonempty ordered list). It identifies the initialization, all-path monotone update and test, not an unchecked prose assertion. Admission must independently establish that each path preserves the declared progression, no other write invalidates it, and the condition is satisfied within max_iterations under every valid input. Input-dependent bounds require a provable finite declared range; this v1 literal-proof form refuses loops whose bound cannot be established with these fields. No loop means []. Manifest omissions/duplicate targets or failed proof refuse `unbounded_perform`; annotations do not manufacture proof.

`hazards` is a list of `{hazard_id,target,reachability_recipe_ids,observable}` with >=2 distinct H1..H8 IDs. Targets resolve to source spans; recipe IDs name complete boundary cases and observable names an emitted field/status/stdout/output effect. Recipes/probes later establish reachability; metadata alone is insufficient. Changed programs require their own source-bound manifest and all the same proofs. These documents contain declarations/contracts only; no manifest instance, hidden recipe or expected result is authored here.

The fixed design requires six dev families, two per domain, four originals/family (24); six structurally different held-out families, two/domain, three originals/family (18). Each original has one changed-original task: 24 dev changes and 18 hidden changes. All variants, changes, recipes, mutants and observations of one family stay in its split. Every original and changed program stays within SUBSET.md and has at least two reachable hazards; authors document which inputs/control paths reach them. A hazard warning alone proves no reachability. No new family count is inferred from variants.

Before GO the custodian compares declared templates and comment/whitespace-normalized token-shape fingerprints against dev; identifier/literal masking is conservative duplication screening, not proof. After parser availability, before hidden candidate dispatch, repeat normalized-AST distinctness checks. Constant/identifier changes alone fail structural separation. Replacement requires logged reseal; exposure retires the entire affected hidden set. No builder sees hidden rejected alternatives or private comparison details. Public commitments bind private manifests without revealing their contents.

## Closed templated-change vocabulary

Each original has exactly one structured edit, one matching short prose rendering, changed-source hash and a later compiler-derived behavior-changing witness. The same edit/prose is supplied to every arm; changed COBOL stays oracle-only. A edits only the specified supported node. Change objects contain exactly manifest_version=1, task_id, original_sha256, target (file, line, byte_start, byte_end, node_kind), operation, before, after, prose, changed_sha256. Spans are zero-based half-open and must resolve uniquely against original bytes; `before` must match. No arbitrary textual patch, multiple edits, source generation, new path or unbounded expression is accepted.

| operation | Target / before / after constraints |
|---|---|
| `replace_numeric_literal` | one numeric literal in arithmetic or numeric comparison; exact decimal strings representable in its context; same numeric type |
| `replace_comparator` | one numeric IF comparison; enum `=`, `<>`, `<`, `<=`, `>`, `>=`; types/operands unchanged |
| `set_rounded` | one arithmetic statement; boolean before/after differ; only default ROUNDED, no mode/handler edits |
| `replace_alpha_literal` | one alphanumeric MOVE/comparison literal; printable ASCII, fits declared context; preserves types |

All other edits refuse `unsupported_change`; invalid/no-op target refuses `change_target`/`change_noop`; failed source hash refuses `change_source_hash`; changed source leaving the grammar refuses `change_out_of_subset`. Neither numeric inequality nor byte inequality alone proves a behavioral change. Later compiler-only witness must show different ordinary observables under a valid case; absent witness returns `change_unwitnessed` and blocks admission, never assumed effective. Changed source must preserve family identity, finite loop proof and two reachable hazards, so an edit that removes a required hazard is inadmissible even if syntactically valid. No multi-node year algorithm replacement or free-English comprehension claim.

## Task and partition bindings

Each task binds program_id, family_id, split, panel=`unchanged|change`, original_sha256, oracle_source_sha256, fields_sha256, recipe_sha256, generator_sha256 and change_sha256 (null only for unchanged). A change panel's oracle_source_sha256 equals its changed_sha256; arm payloads still contain only original source plus structured edit/prose. Freeze before first hidden dispatch. Each task has exactly 32 valid loop and128 valid verification CaseBundles with disjoint byte hashes; original and changed tasks have separate sealed partitions. Required scenario/boundary coverage and quarantine counts are manifest entries, not invented observations. Counts, independence, execution and licenses remain PENDING.
