# Families and change tasks v1

No corpus is authored here. A family is the tuple domain + control-flow template + hazard theme, not an individual program, rename, constant set or variant. Domains are `decimal_fees`, `sequential_status`, `year_window`. Family metadata keys: manifest_version=1, family_id, split, domain, template_id, template_description, hazard_ids, program_ids, author_provenance_sha256. Split is `dev|heldout`; hazards reference H1..H8 in HAZARDS.md. Never make held-out IDs/content available to the builder before authorized burn.

## ProgramManifest

The author-written program manifest has exactly `manifest_version`, `program_id`, `source_sha256`, `family_id`, `split`, `input_fields_sha256`, `output_fields_sha256`, `allowed_return_codes`, `loops`, `hazards`, `provenance_sha256`. Version is integer1; IDs/hashes follow GENERATOR.md; split matches the family. Field documents describe external input/output layouts separately. `allowed_return_codes` is a nonempty sorted unique list of integers0..255, including0; no runtime fault is converted into a declared code. Every RETURN-CODE assignment must resolve to this list by static constant/range reasoning.

`loops` lists every PERFORM UNTIL exactly once in increasing source byte order. Each entry has exactly `target`, `paragraph`, `induction_field`, `initial`, `step`, `relation`, `limit`, `max_iterations`, `proof`. Target is `{file,line,byte_start,byte_end}` resolving to that source statement; paragraph/induction_field are uppercase declared identifiers. Initial/step/limit are signed integer decimal strings; step is nonzero; relation is one SUBSET comparison; max_iterations is integer1..64. Proof is an object with exactly `initialization_span`, `update_spans`, `exit_span`, each span using the same target shape (update_spans is a nonempty ordered list). It identifies the initialization, all-path monotone update and test, not an unchecked prose assertion. Admission must independently establish that each path preserves the declared progression, no other write invalidates it, and the condition is satisfied within max_iterations under every valid input. Input-dependent bounds require a provable finite declared range; this v1 literal-proof form refuses loops whose bound cannot be established with these fields. No loop means []. Manifest omissions/duplicate targets or failed proof refuse `unbounded_perform`; annotations do not manufacture proof.

`hazards` is a list of `{hazard_id,target,reachability_recipe_ids,observable}` with >=2 distinct H1..H8 IDs. Targets resolve to source spans; recipe IDs name complete boundary cases and observable names an emitted field/status/stdout/output effect. Recipes/probes later establish reachability; metadata alone is insufficient. Changed programs require their own source-bound manifest and all the same proofs. These documents contain declarations/contracts only; no manifest instance, hidden recipe or expected result is authored here.

The fixed design requires six dev families, two per domain, four originals/family (24); six structurally different held-out families, two/domain, three originals/family (18). Each original has one changed-original task: 24 dev changes and 18 hidden changes. All variants, changes, recipes, mutants and observations of one family stay in its split. Every original and changed program stays within SUBSET.md and has at least two reachable hazards; authors document which inputs/control paths reach them. A hazard warning alone proves no reachability. No new family count is inferred from variants.

Before GO the custodian compares declared templates and comment/whitespace-normalized token-shape fingerprints against dev; identifier/literal masking is conservative duplication screening, not proof. After parser availability, before hidden candidate dispatch, repeat normalized-AST distinctness checks. Constant/identifier changes alone fail structural separation. Replacement requires logged reseal; exposure retires the entire affected hidden set. No builder sees hidden rejected alternatives or private comparison details. Public commitments bind private manifests without revealing their contents.

## Closed templated-change vocabulary

Each original has exactly one structured edit, one matching short prose rendering, changed-source hash and a later compiler-derived behavior-changing witness. The same edit/prose is supplied to every arm; changed COBOL stays oracle-only. A edits only the specified supported node. Change objects contain exactly manifest_version=1, task_id, original_sha256, target (file, line, byte_start, byte_end, node_kind), operation, before, after, prose, changed_sha256. Spans are zero-based half-open and must resolve uniquely against original bytes; `before` must match. No arbitrary textual patch, multiple edits, source generation, new path or unbounded expression is accepted.

| operation | Target / before / after constraints |
|---|---|
| `replace_numeric_literal` | one numeric literal in arithmetic or numeric comparison; exact decimal strings representable in its context; same numeric type |
| `replace_comparator` | one numeric IF comparison; enum `=`, `<>`, `<`, `<=`, `>`, `>=`; types/operands unchanged |
| `set_rounded` | one arithmetic statement; boolean before/after differ; only default ROUNDED, no mode/handler edits |
| `replace_alpha_literal` | one alphanumeric MOVE/comparison literal; printable ASCII, fits declared context; preserves types |

All other edits refuse `unsupported_change`; invalid/no-op target refuses `change_target`/`change_noop`; failed source hash refuses `change_source_hash`; changed source leaving the grammar refuses `change_out_of_subset`. Neither numeric inequality nor byte inequality alone proves a behavioral change. Later compiler-only witness must show different ordinary observables under a valid case; absent witness returns `change_unwitnessed` and blocks admission, never assumed effective. Changed source must preserve family identity, finite loop proof and two reachable hazards, so an edit that removes a required hazard is inadmissible even if syntactically valid. No multi-node year algorithm replacement or free-English comprehension claim.

## Task and partition bindings

Each task binds manifest_version=1, task_id, program_id, family_id, split, panel=`unchanged|change`, original_sha256, oracle_source_sha256, fields_sha256, recipe_sha256, generator_sha256 and change_sha256 (null only for unchanged). Freeze before first hidden dispatch. Each task has exactly 32 valid loop and128 valid verification CaseBundles with disjoint byte hashes; original and changed tasks have distinct task IDs and separate sealed partitions. Required scenario/boundary coverage and quarantine counts are manifest entries, not invented observations. Counts, independence, execution and licenses remain PENDING.

### Task paired-recipe index

Task `recipe_sha256` binds the **actual stored bytes** of one task-level paired-recipe index. It does not bind a single native GENERATOR partition recipe, a generation receipt, a canonical JSON digest or candidate-derived output. The index is a distinct JSON artifact with exactly these keys:

| Key | Strict value / join |
|---|---|
| manifest_version | integer1, never boolean |
| task_id, program_id, family_id | IDs exactly equal the enclosing task binding |
| split | dev or heldout, exactly the task split |
| panel | unchanged or change, exactly the task panel |
| corpus_version | nonempty ASCII ID under GENERATOR.md's ID rule |
| fields_sha256 | actual input-field document digest, exactly task.fields_sha256 |
| recipes | closed object with exactly loop and verification |

Each `recipes` value is exactly `{path,sha256}`. Path is a nonempty relative forward-slash path resolved under the existing admission evidence root; forbid absolute/drive/UNC paths, backslashes, control bytes, empty components, `.`/`..` components and symlink escapes. Both paths resolve to distinct native recipe artifacts; their raw SHA256 digests must differ. A digest is lowercase64 hex and hashes actual read bytes without newline/JSON normalization. Repeated resolved paths, substituted/corrupt bytes or an unreadable/missing artifact cannot satisfy this binding. This new index is a native task artifact, separate from any existing gate-envelope reference format.

Both referenced documents retain GENERATOR.md's unchanged closed partition-recipe vocabulary. Each must have partition equal its recipes key, exactly matching corpus_version, family_id, program_id and task_id from the index, and original collision_counter integer0. Do not add split, panel or source keys to the native recipes: task identity joins split/panel through the index. The referenced input-field document must still bind the task's actual oracle source, and all original/oracle-source, generator, case and provenance commitments remain required. Neither an index nor a matching digest proves valid cases, generation, oracle execution or secrecy. The index and both native recipes require their own actual-byte provenance sidecars (artifact_kind recipe) and inventory entries under the existing provenance contract. Original/change tasks each get their own index; do not reuse a task ID to connect both panels.

Digest namespaces follow INT construction ruling RULING-task-recipe-index-r4.md. Task/index.fields_sha256 commits to **raw artifact bytes**. Each native recipe.fields_sha256 commits instead to **canonical JSON of that same field document**. Resolve the exact raw field artifact already bound by task.fields_sha256, check that raw hash first, then strictly decode it under GENERATOR.md and derive its canonical SHA256 for both native recipe checks. Do not require raw/canonical equality, accept either digest as an alternative, infer fields from cases, or silently normalize the raw artifact check. Harmless whitespace/key-order differences may change the raw hash while leaving the canonical commitment unchanged; each still has its own mandatory check.

Similarly, recipes[partition].sha256 binds **raw native recipe bytes**, whereas generation receipt.recipe_sha256 binds **canonical JSON of that native recipe**. Verify the raw recipe reference, strictly decode/validate it, and separately derive the canonical recipe hash for that partition's receipt. Receipt.fields_sha256 also remains the canonical field-document hash. Receipt artifact/envelope/sidecar digests bind raw receipt bytes, not either inner canonical member. A receipt's partition must match the native recipe and the index key. These meanings never substitute task.recipe_sha256 (raw paired-index digest) for any partition-local commitment. Any generation_receipts inventory is transport metadata; no wrapper turns it into an actual oracle/trace observation. The index adds no case data, input-generation algorithm, execution receipt or gate bypass.

Native paired-index refusal codes: `paired_recipe_shape` for missing/extra/ill-typed index or reference keys; `paired_recipe_identity` for task/corpus/field identity disagreement; `paired_recipe_partition` for absent/duplicate/wrong partition; `paired_recipe_path` for forbidden/aliased paths; `paired_recipe_hash` for raw digest mismatch. These name contract failures, not claims that the currently accepted gate implements index validation. Missing producers/artifacts stay PENDING; malformed/contradictory evidence is NO-GO under the gate's existing policy. INT must grant consumer reconciliation before later admission integration; source-only construction is not execution evidence.

### Original, edit artifact and changed source

Task `original_sha256` is SHA256 of original COBOL source bytes. For an unchanged panel, task.oracle_source_sha256 equals original_sha256 and task.change_sha256 is null. For a change panel, task.change_sha256 is SHA256 of the **actual structured-edit artifact bytes**, whose closed shape is defined above. It is not the changed-source digest. That edit's `original_sha256` must equal task.original_sha256, its task_id must equal task.task_id, and its nested `changed_sha256` must equal task.oracle_source_sha256, the SHA256 of actual changed oracle-source bytes. The changed source must differ from original source and still requires the compiler-derived behavior-changing witness; digest inequality alone proves no behavior change. No edit self-hash member is introduced. All three raw commitments remain separately named and checked; canonical JSON or source normalization never substitutes for one.

Only the original source plus structured edit/prose enters an arm payload; changed source remains oracle-only. The adopted plan requires these source/edit bindings and supplies no contrary definition of the previously ambiguous task change_sha256. This clarification preserves its one-edit/one-changed-original design and adds no new source or expected answer.
